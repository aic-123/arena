# Arena

**建立在 Scaffold 之上的多人结构化讨论系统。**
**A multi-party structured discussion system built on top of Scaffold.**

[English](README.en.md) · [它不是什么](#它不是什么) · [约束与设计稿 `spec/`](spec/)

AI 是 Secretary / Organizer / Detector，**不是 Judge**（`§C1`）。

> 代码里那些 `§C9 #5`、`§T4.2` 一样的号，指的是 [`spec/`](spec/) 里的约束文档 —— **可以逐条对上**。
> 那几份文档就是这个系统照着建的东西，一并放在仓库里，不用去别处找。

## 它不是什么

先说不做什么，因为它比「做什么」更能说清这个系统：

- **不是 AI 辩论平台。** AI 不生成论点、不评价论点、不判谁赢。它只做三件事：**切分**、**组织**、**发现分歧**。
- **不是投票定胜负的工具。** 投票记的是**公共偏好**，不是真理判定。四个量之间**没有任何算子**能推出「谁更正确」。
- **不是完整产品。** 它是一条**跑通的链**，不是一套能用的服务 —— 没有前端、没有账号、没有部署、没有数据库服务。
- **没有排序轴、没有阈值、没有分数。** 这三条不是「还没做」，是**明令禁止**（`§C7.1` `§C9` #5 #7），有 13 条可执行检查盯着。
- **不做上层归纳、不自动分裂、不自动合并。** 本阶段全程休眠（`§C7.1`）。

## 第 0 步：把代码拿到手

```bash
git clone https://github.com/aic-123/arena.git
cd arena
```

**零第三方依赖，不需要 `pip install`。** 只要 Python 3（3.13 与 3.14 实测）。

## 怎么用（人这一面）

```bash
python cli.py new "加班该不该给钱？" 甲
python cli.py submit debate-0001 甲 "现在的工作强度太大了，所以大家都不愿意往上爬。"
python cli.py confirm debate-0001 draft-0001 甲     # 逐条问，一条一条答
python cli.py view debate-0001
python cli.py chart topic-0001     # 票数的折线图（终端 Braille 文本图）
python cli.py observe
```

库默认 `arena.db`（`ARENA_DB` 可换）。`python cli.py` 什么都不带就印用法。

**想用网页看和写，而不是用终端：**

```bash
python serve.py                 # → http://127.0.0.1:8765
```

Windows 上也可以直接双击 **`打开界面.bat`** —— 它会起服务、等端口就绪、再开浏览器。

**库不存在也能开。** 界面启动时会自己建表骨架（和 `cli.py` 走同一条路），
所以第一次跑看到的不会是报错，而是「这个库里还没有讨论」+ 一个「开讨论」的输入框。

**网页能做的**：

| 动作 | 替代的命令 |
|---|---|
| 开讨论 | `cli.py new` |
| 提交一段原话 → 切分 | `cli.py submit` |
| **逐条确认**（每条各自选「没被歪曲 / 被歪曲了」） | `cli.py confirm` |
| 换说法重交 | `cli.py rewrite` |
| 记下「不提交」 | 确认时敲 `q` |
| 看讨论 / 观测点 / 票数 | `cli.py view` / `observe` / `chart` |

**它不是「另起一套写路径」。** 上面每个动作都只是**调度**
`debate.py` / `confirm.py` 里**和 `cli.py` 调的那同一批函数**。
证据是硬的：网页走完一遍「点歪曲 → 重写」，`observe` 里的**换说法率会动**
（`1 / 1`），而那个量只有在真正的写路径上才算得出来。

**确认流程在网页上仍然是一条一条的。** 一屏列完（那是版式），
但每条各自作答 —— **没有「全部确认」这种按钮**。而且：

- **不回答 ≠ 同意**：有任一条没答，整份都不写
- **「不提交」是要点下去的按钮**，不是关掉页面 —— 点它记 `draft_abandoned`；
  关掉页面**一个字都不写**（分不出「你走了」还是「脚本坏了」）
- 节点类型用默认时，**那个默认会记进库里**，可抽检、可改判

**关于「命题类型为什么都是 Claim」。** 这是个常见误读，说清楚：

| 输入 | 引擎能判什么 | 结果 |
|---|---|---|
| 「工作强度太大，**所以**不愿往上爬」 | 有两种可能（因果即主张 / 因果即推断），字面分不出来 | 给候选 `[Claim, Evidence]`，**默认 Claim**，人可改判 |
| 「网上的讨论在变情绪化」（无连接词） | **没有可判的东西** —— 原文里没有连接词可读 | `Claim`，记为 `type_basis=no_candidate_default` |

两者都落到 `Claim`，但**原因不同**，库里分开记在 `type_basis` 里。
所以「全是 Claim」不等于「类型判定没工作」——
第二种情况里，引擎**确实没有可判的东西**，那不是一个失败的判断。

分清「没有可判的东西」与「判了但没说」，靠的就是 `type_basis` 这个字段：
`user_resolved`（人定的）/ `causal_candidate_default`（有候选走默认）/
`causal_connective`（连接词本身成的节点）/ `no_candidate_default`（无连接词可读）。

**身份在页面顶部填一次**，存在浏览器 Cookie 里。没填就不让写 ——
写入要记「谁提出来的」，`§C2.4` 的观测点按人算，这个不能空。

**唯一没接的是投票的「投」。** `§C12` 要求先定「选项怎么呈现给人」，
那是产品判断（DECLARATION §13.5），猜的代价高于问，所以停在那里。
「看票数」（`chart`）是通的。

**零第三方依赖**，只用标准库 `http.server` —— 不是没用成熟方案，
是 `§T5`（引入依赖是必须停下来的阻断项）把方案限定在了标准库这一档。

但它**先印换手次数再印异常**：换手是 0 的话，那句「未暴露」就没有分母，不算证据。

零第三方依赖。只需 Python 3。CI 在 `ubuntu-latest` 与 `windows-latest` 上跑全部检查。

**两条写路径已统一**（2026-09-25，DECLARATION §14）：`add_position` 那条
「不分割、不逐条确认、只存 `{text, raw_text}`」的路**已删除**，
`open_debate` 也不再自带 Topic。现在写内容只有一条路：
`confirm.propose()` → `confirm.confirm(reviewed=[…])` → `open_topic()` / `add_to_topic()`。
所以 Topic 只可能由一次**逐条确认**产生，`§C5.6` 的两个观测点不再有「永远算不出」的死角。

**改判率的口径与读数都定了**（2026-09-25，DECLARATION §14.4）：

- **口径**：`contains` 这类**用户拒不了的结构边排除出分母**（分子分母用**同一个**
  `kind NOT IN` 判据）。后果要看清 —— 机器产的判断边现在只剩一对因果边，
  所以改判率**只在含因果命题的提交上存在**；一句普通陈述分母是 0。
- **接通**：**不做**「拒绝一条边」的界面。`debate.reject_edge()` 只有测试在用，
  所以从 `cli.py` 看分子**长期恒为 0** —— 于是这个 0 印成
  「算不出 —— 分子产不出……」，**不再是 `0.0000`**。

## 三条不靠自觉的约束

它们写在存储层里，没有第二条写入路径：

- **`§C3.2`** Relation 是可追踪对象 —— 独立表、有身份、有来源、可拒绝、被拒绝后**不删**（否则改判率算不出来）
- **`§C10`** 禁止覆盖式更新 —— 旧版本一行都不改；并发修改自然分叉，且**系统不替你挑分支**
- **`§C9` #3** 机器不得自授 `verified` —— 只有 `grant_verified(hook=...)` 一条路，且必须具名钩子

## 本仓库刻意不做的事

不排序、不打分、不加锁、不设阈值、不做上层归纳。
依据见 `DECLARATION.md` §4 —— 这些不是省略，是 `§C11.2` `§C7.1` `§C7.2` 明确要求的。

**允许的派生视图只有三处**，都是只读、不写回、不建对象：

- `observe.py` 的比率 / 计数 —— 「算不出」有**两个**来源，都在行内写出来：
  **分母为 0**（还没开始记）与**分子产不出**（产品里没有产生它的动作，
  那个 0 是「测不了」不是「零」）。判据：**一个数如果它的「0」和「没有」分不开，
  就不许印成 0。**
- `hints.py` 的子问题提示 —— 只指回用户原文里的位置，**不生成任何问题**
  （`§C2.0`：系统不得代替用户提出议题，只能发现并提示）
- `vote.py` 的 `chart()` 折线图 —— 只画**已有票**的累计，不排序、不设阈值、
  **不跨问题版本**（旧票属于旧问题，`§C12.5`）
