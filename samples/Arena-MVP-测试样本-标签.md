### D2 · 有研究说每天喝咖啡能降低心脏病风险，所以我每天喝三杯

| 节点 | 标签 | 内容 |
|---|---|---|
| n1 | `Claim` | 我每天喝三杯咖啡 |

## E. 反驳 / 质询

### E1 · 你说读书有用，但很多成功的人根本没读多少书

| 节点 | 标签 | 内容 |
|---|---|---|
| n1 | `Claim` | 读书有用（**被质询目标**） |
| n2 | `Counterexample` | 很多成功的人没读多少书 |

**关系**：n2 ─`contradicts`→ n1　**或**　n2 ─`qualifies`→ n1　⚠️ **见缺口 ③**

**注**：这个歧义是**核心考察点**：
- 反例否定的是**结论**「读书有用」→ 挂 `contradicts`
- 反例否定的是**推理链**「读书 → 成功」→ 挂 `qualifies`
- **两种挂法含义不同，系统必须区分，且不得自动决定**

### E2 · 这个数据是三年前的，现在情况早变了

| 节点 | 标签 | 内容 |
|---|---|---|
| n1 | `Evidence` | 这个数据（**被质询目标**） |
| n2 | `Counterargument` | 数据是三年前的 + 情况已变 |

**关系**：n2 ─?→ n1　⚠️ **见缺口 ④**

**注**：质询落在 **Evidence 的 `temporal validity` 属性**上，
**不是**落在 Claim 上 —— 系统要能表达「反对的是证据，不是结论」。

⚠️ 这里刻意**不新造** `Challenge` 标签：n2 的节点类型就是 `Counterargument`，
问题出在 **`challenged_by` 的起点不允许是 `Evidence`**，不在标签本身。
**不要为了绕开一个定义域问题而新增标签** —— 那会把设计缺口藏起来。

### F3 · 这个政策好不好，取决于你说的是短期还是长期 —— 短期有效，长期有害

| 节点 | 标签 | 内容 |
|---|---|---|
| n1 | `Topic` | 这个政策好不好 |
| n2 | `Subtopic` | 时间尺度（短期 / 长期） |
| n3 | `Claim` | 短期有效 |
| n4 | `Claim` | 长期有害 |

**关系**：n3 ─`related_to`→ n2　n4 ─`related_to`→ n2　⚠️ **见缺口 ⑤**

**注**：**F 组最难的一条。**
n2 不是「另一个问题」，而是**同一问题的另一个评价维度**。
两条路都说得通，**系统不得自己选**：
- **`nest`**：把 n1 拆成「短期效果」和「长期效果」两个独立 Debate
- **`refines`**：n1 被 n2 **细化**成两个子主张（不新建 Scaffold）

判据是 §8.2 四条嵌套门槛（独立生命周期 / 独立上下文 / 脱离父节点仍成立 / 需独立讨论）。

## ⚠️ 标注中暴露的 5 个 ontology 缺口

**这些不是标注错误，是设计缺口。** 用测试样本把它们打出来，正是样本的用途。

### 缺口 ①　因果主张怎么表达

**影响样本**：B1、B2、B4、D1、D3

系统现有关系：

```
六种 Relation      contains / derived_from / supports / contradicts / refines / related_to
六种 Debate 关系    supports / contradicts / qualifies / assumes / explains / challenged_by
```

**没有任何一种能表达「A 导致 B」这个命题与它两端的关系。**

B1 里 n3「n1 导致 n2」是一个**独立 Claim**，但它跟 n1、n2 挂什么关系？
`contains` 不对（n3 不包含它们），`related_to` 太弱（丢失因果方向）。

**需要的是一类「因果主张 ↔ 前提 / 结论」的关系。** 请定名。

### 缺口 ②　「所以 / 说明 / 因为」有两种形态

**影响样本**：B1（因果即主张）vs D1 / D2 / D4（因果即推断）

| 形态 | 例子 | 结构 |
|---|---|---|
| **因果即主张** | B1「强度大**所以**不愿晋升」 | n1、n2 都是断言的事实，**因果本身是主张** |
| **因果即推断** | D1「朋友加班**所以**行业压榨」 | n2 是**证据**，n1 是**主张**，因果是 **`supports` 关系** |

**同样一个「所以」，结构完全不同。** 系统必须区分这两者，否则会把证据误判成主张。

### 缺口 ③　反例挂在哪：`contradicts` 还是 `qualifies`

**影响样本**：E1

- 否定**结论** → `contradicts`
- 否定**推理链** → `qualifies`

现有 ontology 两种都有，但**没有判据**说明何时用哪个。**这是最容易被静默决定的地方。**

### 缺口 ④　质询落在 Evidence / Assumption 上时怎么挂

**影响样本**：E2、E3

系统定义的 `challenged_by` 只有一条：

```
Claim ──challenged_by──→ Counterargument
```

但真实辩论里最常见的有效反驳是：
- **质询证据的属性**（E2：数据过时 → `temporal validity`）
- **质询假设**（E3：理性人假设不成立）

**这两类都落不进现有定义。** 需要扩展 `challenged_by` 的**定义域**（允许从 Evidence / Assumption 出发）。

### 缺口 ⑤　`nest` 还是 `refines`

**影响样本**：F3

「同一问题的另一个评价维度」—— 这既可能是新 Debate，也可能只是原问题的细化。
**两条路都合理，系统不得自己选。** 需要一条判据把 §8.2 的四条门槛变成可执行的检查。
